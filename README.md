### Мы начали не с приложения, а с исследования сезонных биологических угроз Центральной России. Выяснили, что официальные службы публикуют качественные данные, а активность разных вредителей связана с различными измеримыми факторами. Одновременно выяснилось, что по одной погоде нельзя достоверно предсказывать появление вредителя. Поэтому мы отказались от идеи прогнозатора и разработали систему оценки сезонного риска. Она получает текущую погоду, применяет отдельные правила для каждого вида и объясняет пользователю, почему риск сейчас повышен и какие профилактические действия рекомендованы

---

Проект представляет собой образовательное веб-приложение для оценки сезонного риска активности клещей и вредителей растений на территории Центральной России.

Приложение получает актуальные погодные данные для выбранной пользователем территории и сопоставляет их с правилами сезонной активности конкретных биологических угроз.

На основании полученных данных система определяет один из четырех уровней сезонного риска:

- низкий;
- умеренный;
- повышенный;
- высокий.

Для каждой оценки система показывает:

- название угрозы;
- текущий уровень риска;
- факторы, повлиявшие на результат;
- краткое объяснение;
- профилактические рекомендации;
- источник, на основании которого сформированы правила оценки.

Проект не предназначен для точного прогнозирования фактического появления вредителя в конкретной точке.

Результат работы системы показывает, насколько текущие сезонные и погодные условия соответствуют известным условиям активности рассматриваемой угрозы.

---

## Основание для разработки

Проект является результатом предварительного исследования сезонных биологических угроз в Центральной России.

В ходе исследования установлено, что активность различных видов зависит от разных факторов.

Например:

- для иксодовых клещей значимы сезон и температура;
- для колорадского жука — температура почвы;
- для капустной тли — температура и влажность;
- для яблонной плодожорки — накопленная сумма эффективных температур.

Исследование также показало, что погодные условия позволяют оценивать период повышенного риска, но не позволяют достоверно утверждать о фактическом наличии конкретного вредителя.

Поэтому в проекте используется модель **оценки сезонного риска**, а не модель точного прогнозирования появления вредителей.

---

## Выявленная проблема

Обычному жителю Центральной России, владельцу дачного, садового или огородного участка сложно своевременно определить, какие сезонные биологические угрозы актуальны в данный момент для его региона и объекта интереса. Официальная информация существует, но распределена между различными санитарными и аграрными источниками, публикуется в разных форматах и требует самостоятельного поиска и интерпретации.

Обычному пользователю сложно самостоятельно определить, какие сезонные биологические угрозы актуальны в данный момент для его территории.

Информация существует в официальных источниках, однако:

- относится к различным областям;
- публикуется разными организациями;
- распределена по региональным ресурсам;
- представлена в разных форматах;
- требует самостоятельного поиска;
- требует специальных знаний для интерпретации погодных и сезонных факторов.

Пользователь может видеть текущую температуру, влажность и прогноз погоды, но без дополнительных знаний не может определить, что эти показатели означают с точки зрения активности конкретного вредителя.

---

## Предлагаемое решение

Автоматически оценивать соответствие текущих погодных и сезонных условий известным условиям активности конкретных биологических угроз и заранее информировать пользователя о повышенном риске.

Приложение должно автоматически выполнять следующую последовательность:

```text
Выбор территории
        ↓
Получение погодных данных
        ↓
Определение актуальных угроз
        ↓
Применение правил для каждой угрозы
        ↓
Определение уровня риска
        ↓
Объяснение результата
        ↓
Профилактические рекомендации
```

Таким образом, приложение преобразует профессиональные сведения о сезонных условиях активности вредителей и текущие погодные данные в понятный обычному пользователю индикатор риска.

## Возможности MVP

PestWatch поддерживает три профиля оценки:

- **Человек** — оценка сезонной активности иксодовых клещей;
- **Огород** — оценка риска вредителей овощных культур;
- **Сад** — оценка риска вредителей плодовых культур.

В MVP реализована оценка четырех биологических угроз:

| Угроза | Профиль | Основные факторы |
| --- | --- | --- |
| Иксодовые клещи | Человек | температура воздуха, влажностные условия |
| Капустная тля | Огород | температура и влажность |
| Колорадский жук | Огород | температура почвы |
| Яблонная плодожорка | Сад | накопленная сумма эффективных температур |

Для каждой выполненной оценки PestWatch показывает:

- уровень риска;
- факторы, участвовавшие в расчёте;
- сохранённые значения факторов;
- условия, с которыми они сравнивались;
- объяснение результата;
- профилактические рекомендации;
- источники, на основании которых сформированы правила.

### Обычная оценка

В обычном режиме пользователь указывает населённый пункт, регион и страну.

PestWatch:

1. определяет координаты территории;
2. получает необходимые погодные данные;
3. выбирает угрозы для указанного профиля;
4. рассчитывает факторы риска;
5. формирует результат;
6. сохраняет выполненную оценку в истории.

### Демонстрационный режим

Demo Mode позволяет изучить работу PestWatch без зависимости от текущей погоды и доступности внешних сервисов.

В демонстрационном режиме используются заранее подготовленные детерминированные сценарии с фиксированными исходными данными.

Demo Mode использует тот же механизм оценки риска, что и обычный режим, но не обращается к внешним погодным API.

### История оценок

Выполненные оценки автоматически сохраняются в локальной базе данных.

В истории отображаются:

- место;
- профиль;
- дата оценки;
- время выполнения;
- источник результата — обычная оценка или Demo.

Сохранённую оценку можно открыть повторно.

Историческая страница показывает именно данные, сохранённые в момент выполнения оценки. PestWatch не выполняет повторный расчёт и не получает новые погодные данные при просмотре истории.

## Ограничения MVP

PestWatch является системой оценки сезонного риска, а не системой точного прогнозирования появления вредителей.

Текущая версия имеет следующие ограничения:

- поддерживается ограниченный набор биологических угроз;
- правила ориентированы на условия Центральной России;
- результат зависит от доступности и качества погодных данных;
- система не использует данные непосредственных наблюдений вредителей в конкретной точке;
- отсутствуют пользовательские аккаунты и персонализация истории;
- история является общей для экземпляра приложения;
- сравнение результатов разных периодов пока не реализовано;
- приложение не заменяет рекомендации санитарных, медицинских или агрономических специалистов.

## Архитектура

PestWatch разделяет получение данных, подготовку входного контекста, расчёт риска и представление результата.

Основной поток обычной оценки:

```text
Web UI
  ↓
Assessment API
  ↓
Location Service
  ↓
Risk Assessment Orchestrator
  ↓
Weather / Historical Weather
  ↓
Risk Context Preparation
  ↓
Threat-specific Risk Calculator
  ↓
Assessment Persistence
  ↓
Result / History
```

В Demo Mode внешние погодные источники заменяются детерминированными сценариями, при этом основной механизм расчёта риска остаётся тем же.

## Установка

Для проекта используется Python 3.12.

Проверить доступные версии Python в Windows:

```powershell
py -0p
```

Создать виртуальное окружение:

```powershell
py -3.12 -m venv .venv
```

Активировать виртуальное окружение в PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

После активации в начале строки терминала должно появиться:

```text
(.venv)
```

Проверить используемую версию Python:

```powershell
python --version
```

Ожидается:

```text
Python 3.12.x
```

Установить зависимости:

```powershell
python -m pip install -r requirements.txt
```

## Запуск приложения

Инициализировать базу данных и каталог угроз:

```powershell
flask --app run.py init-db
```

Запустить Flask-приложение:

```powershell
python run.py
```

После запуска приложение доступно по адресу:

```text
http://127.0.0.1:5000
```

Для остановки сервера:

```text
Ctrl+C
```

## Запуск тестов

### UI E2E-тестирование

Критические пользовательские сценарии PestWatch автоматизированы с помощью **Playwright + pytest**.

E2E-тесты запускают приложение через реальный локальный HTTP-сервер и взаимодействуют с ним через браузер Chromium.

### Подготовка окружения

Установить Python-зависимости:

```bash
pip install -r requirements.txt
```

### Установить Chromium для Playwright:

```bash
python -m playwright install chromium
```

### Запуск всех тестов

```bash
pytest -q
```

### Запуск тестов без браузерных E2E

```bash
pytest -m "not e2e" -q
```

### Запуск только UI E2E-тестов

```bash
pytest -m e2e -q
```

### Запуск E2E с отображением браузера

По умолчанию Playwright запускает браузер в headless-режиме.
Для локальной отладки можно запустить тесты с видимым окном Chromium:

```bash
pytest -m e2e -q --headed
```

### Запуск отдельных E2E-сценариев

Demo Mode:

```bash
pytest tests/e2e/test_demo_mode.py -q
```

Обычная оценка риска:

```bash
pytest tests/e2e/test_real_assessment.py -q
```

### Тестовое окружение E2E

При запуске E2E-тестов:

- PestWatch поднимается на временном локальном HTTP-сервере;
- используется отдельная временная SQLite-база данных;
- данные БД очищаются перед каждым браузерным тестом;
- каталог угроз создаётся заново после очистки БД;
- внешние сервисы геокодирования и погоды заменяются детерминированными тестовыми реализациями;
- тесты не зависят от доступности Open-Meteo;
- браузером по умолчанию является Chromium.

При этом E2E-тесты используют реальные контроллеры, сервисы оценки риска, оркестратор, калькуляторы, репозитории и механизм сохранения результатов PestWatch.

### Что проверяют E2E-тесты

Browser E2E-слой покрывает ключевые пользовательские сценарии:

- открытие приложения в браузере;
- выполнение оценки в демонстрационном режиме;
- отсутствие обращения к обычному API оценки при работе в Demo Mode;
- сохранение Demo Mode при переходах между страницами;
- явный выход из Demo Mode;
- просмотр подробностей результата оценки;
- выполнение обычной оценки риска;
- отсутствие обращения к Demo API при обычной оценке;
- сохранение выполненной оценки в истории;
- открытие сохранённой оценки;
- отображение сохранённых результатов, факторов и исходных данных.

### Границы E2E-слоя

E2E-тесты предназначены для проверки критических пользовательских потоков и интеграции основных компонентов приложения.

Они намеренно не дублируют исчерпывающие проверки:

- правил расчёта риска;
- граничных значений;
- отдельных факторов риска;
- API-контрактов;
- содержимого рекомендаций и источников;
- отдельных состояний UI.

Эти проверки выполняются на более быстрых уровнях — unit, integration и API tests.

Такой подход позволяет сохранить browser suite небольшим, стабильным и пригодным для регулярного запуска.
